# Pre-registration v13 — FROZEN 2026-10-12, before any v13 run

**Why v13.** In v12, which rules file an agent reached depended on whether the ROUTER linked it.
A cited file was reached in 5 of the 7 cases where the router links one of the case's cited files,
and in 1 of the other 13 (Fisher one-sided p = 0.007, computed from v12's transcripts with
`route.py`, descriptive). Runs that did not reach one loaded the router and went straight to the
project's code. The router links files next to *security* words (authentication, sessions,
uploads). Tasks are phrased in the words of what the code does ("export the catalog as CSV",
"notify a callback URL"), so nothing in the router matched them.

SOTA-skills ROADMAP 73 option (o), operator decision 2026-10-12: put the code-rules hook's trigger
table in the router itself. Each rules file is linked next to the words of what code does ("fetches
a URL", "writes CSV or spreadsheet output", "builds an email or a message header"). Above the table
sits v10's paragraph: the rules are part of the task, so build each with a conservative default and
do not hand it back. The table is generated by `scripts/code-rules-hook.py --router-table`, and that
script's self-test fails if the router's copy differs. This is the version for every host that
cannot run the hook (Codex, Copilot, Gemini, Cursor), so the arm has **no hook of any kind**.

## Validity, manipulation, decision rule (enforced by `analyze_v13`)

- **INVALID** if:
  - a row's arm is anything other than `installed+table`;
  - either arm has more than one router, or both arms have the same one;
  - a row's prompt named rules files;
  - any row carries `hint_router`, `hint_skill`, `hint_code`, `linked_table` or `hint_label`;
  - a control row carries `hint_apply` or `table_router`;
  - a row lacks the reach fields;
  - an arm has no valid rows.
- **`hint_apply` is expected in the treatment.** The router's table carries v10's paragraph, so it
  is not a hook there.
- **MANIPULATION FAILED** if the table reached fewer than 0.5 of the treatment's valid runs.
- **Primary: a cited rules file reached** (a tool input names it), paired by case against v12's
  rows, with v12's rule and thresholds:
  - **SUPPORTED** iff the exact one-sided sign test gives p < 0.05 and reach rises by ≥ 0.20;
  - **NULL** iff the rise is ≤ 0.05;
  - **INCONCLUSIVE** otherwise.
- **Secondary: rule tests**, v7's paired rule:
  - **SUPPORTED** iff p < 0.05 and the rise is ≥ +0.09;
  - **NULL** iff it is ≤ +0.02;
  - **INCONCLUSIVE** otherwise.

  It does not qualify the primary. Reference points, not compared formally: v7's named-files arm
  0.868, and v10's hook arm 0.906.

## Descriptive, decided now

- Runs past the router; failed rules Reads; the route to each first cited file (`route.py`).
- **Grep hits on a cited file.** The reach metric does not count them: v12's w07 and w09 found
  cited text by grep and score "not reached". Counted for both arms from the transcripts, reported
  beside the primary, never instead of it.
- For each failing rule test, whether the run named the risk and handed it back (as in v9).
- Spec tests, mean cost, turns, rules lines seen.

**What each result would mean.**
- **SUPPORTED:** keep the table and build a fresh case set before claiming it, because the table
  was tuned on these cases.
- **NULL:** links next to task words do not get agents there either. Remove the table from the
  router, return the router's 30 lines to their content, and leave the hook as the only route.
- **INCONCLUSIVE:** the operator decides.
